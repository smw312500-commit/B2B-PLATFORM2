========================================
백엔드 — 만들어야 할 API 목록
========================================

[ 수신 API — 각사 agent가 호출하는 엔드포인트 ]

POST /api/collected-release
  → 생산사 3곳(옷감사/라벨사/지퍼단추사)이 출고완료 시 전송
  → 받는 데이터: company_id, item_name, quantity, unit, due_date, status, label_code
  → collected_release 테이블에 저장
  → 저장 후: 같은 label_code로 3사 모두 출고완료인지 체크
     → 3사 모두 완료면 → dispatch 테이블에 배차 요청 자동 생성

POST /api/logistics/complete
  → 물류사가 배송완료 시 전송
  → 받는 데이터: delivery_id, company_id, destination, complete_date, status
  → dispatch 테이블 status → "완료" 업데이트

[ 조회 API — 프론트엔드에서 사용 ]

GET /api/dashboard/summary
  → 오늘 기준 전체 현황 숫자
  → 응답: { total_releases, completed_releases, pending_dispatches, active_insights }

GET /api/collected-release
  → 수집된 출고 목록 (날짜 범위 필터 지원)
  → Query params: ?from=YYYY-MM-DD&to=YYYY-MM-DD

GET /api/labelcode/{label_code}/status
  → 라벨코드 9자리로 3사 출고 현황 조회
  → 응답: { label_code, 옷감사: {status, item_name, qty}, 라벨사: {...}, 지퍼단추사: {...} }
  → 3사 연결 상태를 한눈에 보여주는 핵심 API

GET /api/dispatch
  → 배차 목록 조회
  → 상태: 대기/배차완료/운행중/완료

GET /api/insights
  → 저장된 AI 인사이트 목록
  → insight_type: 납기위험/트렌드/물류최적화

POST /api/insights/analyze
  → GPT API 호출하여 인사이트 생성
  → 최근 30일 collected_release 데이터 분석
  → 납기위험 / 패션트렌드 / 물류최적화 인사이트 3가지 생성
  → insight_log 테이블에 저장 후 반환

GET /api/company-info
  → 4개사 기본 정보 조회

insight_log

  related_code(라벨코드), created_at

========================================
백엔드 — 핵심 비즈니스 로직
========================================

[ 3사 출고완료 체크 로직 ]
POST /api/collected-release 수신 시:
  1. collected_release에 저장
  2. 해당 label_code로 company_id 1,2,3 모두 status="출고완료"인지 확인
  3. 모두 완료 → dispatch 테이블에 새 행 생성
     pickup_date = due_date - 2일 (이동1일 + 여유1일)
     destination은 label_code에서 판단하지 않고 "인천항"을 기본값으로

[ GPT AI 인사이트 생성 로직 ]
POST /api/insights/analyze 호출 시:
  최근 30일 collected_release 데이터를 GPT에 전달
  아래 3가지 인사이트 분석 요청:

  ① 납기위험 감지
     같은 label_code인데 일부 회사만 출고완료이고 납기일이 3일 이내인 경우
     예: "W3MJW01NV — 옷감 완료, 지퍼 미출고, 납기 D-2 위험"

  ② 패션 트렌드 추론
     원목단추(item_name에 "WOOD" 포함) 출고 전월 대비 +20% 이상 → "프리미엄 셔츠 수요 증가"
     폴리에스터+다운(label_code 4번째 자리 D, 원단코드 P) 동시 급증 → "아웃도어 시즌 수요"
     울+재킷(label_code 5번째 자리 W, 4번째 자리 J) 급증 → "고급 울재킷 강세"

  ③ 물류 최적화
     dispatch 대기 건 중 출발지가 같거나 경로가 겹치는 건 묶음 배송 제안

  GPT 응답은 한국어로, JSON 형태:
  [{ "type": "납기위험", "content": "...", "related_code": "W3MJW01NV" }, ...]

========================================
주의사항
========================================

1. 포트 8000 절대 변경 금지
   각사 agent 백엔드의 PLATFORM_API_URL이 http://localhost:8000으로 고정됨

2. CORS 설정 필수
   allow_origins에 포함: http://localhost:5173, http://localhost:5174, http://localhost:3000

3. label_code 없이 오는 데이터도 허용
   옷감사는 label_code를 전송하지 않을 수 있음 → nullable로 처리

4. company_info 초기 데이터는 init_db.py에서 자동 삽입
   이미 있으면 건너뜀 (중복 삽입 방지)

5. GPT API 키 없을 때 대비
   OPENAI_API_KEY 없으면 인사이트 분석 버튼 비활성화 + "API 키 미설정" 안내

6. UI 스타일은 Tailwind 사용, 다른 생산사 agent(라벨agent)와 비슷한 톤 유지
