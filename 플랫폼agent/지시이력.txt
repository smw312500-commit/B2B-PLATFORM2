[2026-05-31] 멀티 에이전트 보고 구조 구현 예정

지시: 각사 AI → 플랫폼 AI 보고 구조 추가

각사 AI가 플랫폼으로 보내야 할 데이터:

  생산 스케줄 보고 (POST /api/agent-report/schedule):
  {
    "company_id": 3,
    "company_name": "지퍼단추사",
    "item": "WOOD_BR",
    "qty": 1000,
    "start_at": "2026-05-01 09:00",
    "estimated_completion": "2026-05-02 14:00",
    "status": "진행중"   ← 재조정 시 "재조정"으로 변경
  }

  돌발상황 재조정 보고 (POST /api/agent-report/reschedule):
  {
    "company_id": 3,
    "reason": "기계고장",
    "new_estimated_completion": "2026-05-03 10:00"
  }

  BL 입고 보고 (POST /api/agent-report/import):
  {
    "company_id": 3,
    "material": "원목",
    "qty": 800,
    "arrival_date": "2026-05-05",
    "bl_number": "SINOTRANS-2026-ZP001"
  }

플랫폼 AI가 하는 일:
  - 각사 보고서 수신 (raw DB 아닌 AI 판단 결과)
  - 수출 완료 시각 + 수입 입고 시각 종합
  - 이동시간 매트릭스 적용 → 물류 기사 출발 시각 계산
  - 물류에 지시 (POST http://localhost:8004/api/platform/signal)

결과: [2026-06-02] 완료

    · POST /api/agent-report/reschedule  재조정 보고 수신 + 물류 변경 신호

[2026-06-04 13:53] Agent 간 1:1 보고 채널 UI 추가
----------------------------------------
지시: 플랫폼agent에 각 agent와 API 보고 이벤트를 채팅처럼 확인하는 1:1 보고 채널을 만들 것

  목적:
    생산사/물류사가 자기 DB를 플랫폼에 넘기는 방식이 아니라,
    각 agent가 자기 상황을 판단한 결과만 플랫폼에 보고하는 구조를 화면에서 확인 가능하게 만든다.

  중요한 원칙:
    - 자유채팅 기능이 아니다.
    - 실제 업무 처리는 기존 API JSON 보고로 한다.
    - 채팅 UI는 API 보고 이벤트를 말풍선/타임라인처럼 보여주는 화면이다.
    - 채팅 텍스트를 파싱해서 비즈니스 로직을 돌리면 안 된다.

  플랫폼 채널 구조:
    단체 채팅처럼 만들지 말 것.
    아래 4개 1:1 채널을 분리해서 보여줄 것.
      - 플랫폼 - 라벨
      - 플랫폼 - 물류
      - 플랫폼 - 지퍼단추
      - 플랫폼 - 옷감

  기록 대상 이벤트:
    - 라벨/옷감/지퍼단추 -> 플랫폼
      · /api/agent-report/schedule
      · /api/agent-report/reschedule
      · /api/agent-report/import
      · /api/collected-release
    - 플랫폼 -> 물류
      · /api/platform/signal 전송
      · 배차 요청
      · 픽업 필요 보고
      · 납기 위험 화물 알림
      · 귀로배정 후보 알림
    - 물류 -> 플랫폼
      · 배차 확정 정보
      · 배송 완료 신호
      · 왕복/귀로배정 결과

  권장 데이터 구조:
    report_message 또는 agent_message 테이블/모델을 추가해도 됨.
    필드 예시:
      - id
      - channel: label / logistics / zipper / fabric
      - direction: inbound / outbound
      - source_agent
      - target_agent
      - event_type
      - related_code
      - title
      - summary
      - payload_json
      - status
      - created_at

  백엔드 작업:
    - 기존 agent_report 수신 시 report_message에도 기록
    - collected_release 수신 시 해당 생산사 채널에 기록
    - 물류agent로 signal 전송 시 플랫폼-물류 채널에 outbound 기록
    - 물류agent 완료/상태 수신 시 플랫폼-물류 채널에 inbound 기록
    - 조회 API 추가
      예:
        GET /api/report-channels
        GET /api/report-channels/{channel}/messages

  프론트 작업:
    - 플랫폼 UI에 "Agent 보고 채널" 또는 "보고 채널" 탭 추가
    - 4개 채널을 분리해서 표시
    - 단톡방 느낌이 아니라 플랫폼과 각 agent 간 1:1 업무 보고 화면처럼 구성

  주의:
    - 이 기능은 오케스트레이션 과정을 보여주기 위한 핵심 포트폴리오 UI다.
    - 구현 후 결과에 수정 파일, 추가 API, 추가 테이블 여부를 기록할 것.
