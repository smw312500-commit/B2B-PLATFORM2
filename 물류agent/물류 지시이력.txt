[2026-06-04 13:53] 플랫폼 보고 채널 UI 추가
----------------------------------------
지시: 물류agent에 플랫폼agent와 API 보고 이벤트를 채팅처럼 확인하는 보고 전용 채널을 만들 것

  목적:
    물류agent가 자기 DB 전체를 플랫폼에 넘기는 것이 아니라,
    기사/차량/배차/귀로배정 판단 결과만 플랫폼에 보고하는 흐름을 화면에서 확인 가능하게 만든다.

  중요한 원칙:
    - 자유채팅 기능이 아니다.
    - 실제 업무 처리는 기존 API JSON 보고로 한다.
    - 채팅창은 플랫폼과 물류agent 사이의 지시/보고 이벤트를 말풍선/타임라인처럼 보여주는 UI다.
    - 채팅 텍스트를 파싱해서 비즈니스 로직을 돌리면 안 된다.

  채널:
    - 물류 - 플랫폼 1개 채널만 표시

  표시할 이벤트:
    - 플랫폼 -> 물류
      · /api/platform/signal 수신
      · 픽업 요청
      · 배차 요청
      · 납기 위험 화물 알림
      · 귀로배정 후보 요청
    - 물류 -> 플랫폼
      · 배차 확정 보고
      · 기사/차량 배정 결과
      · 픽업일 계산 결과
      · 왕복/귀로배정 결과
      · 배송 완료 신호

  화면 요구사항:
    - 하단 AI 지시 영역 또는 별도 "플랫폼 보고" 영역에 표시
    - 메시지 방향 구분
      · 플랫폼 -> 물류agent: 수신한 지시
      · 물류agent -> 플랫폼: 내가 보낸 보고
    - 상태 표시: 수신완료 / 배차검토중 / 배차완료 / 귀로배정 연결완료 / 빈차귀환 / 플랫폼 보고 대기

  구현 방향:
    - 기존 routers/platform.py의 /api/platform/signal 수신 시 보고 채널에 inbound 기록
    - auto_dispatch 실행 결과를 보고 채널에 outbound 기록
    - 배송 완료 시 플랫폼으로 보내는 완료 신호를 보고 채널에 outbound 기록
    - 필요하면 report_message 같은 로컬 로그 저장 구조를 추가해도 됨
    - 메시지 문구는 JSON payload를 사람이 읽기 쉽게 요약해서 생성한다
      예: "플랫폼 픽업 요청 수신: 부산시 -> 인천항, 납기 2026-06-08."
      예: "김기사 배차 확정. 귀로 후보 1건 연결 가능."

  주의:
    - 플랫폼 장애가 물류 업무를 막으면 안 됨
    - 보고 실패 시 업무는 계속 진행하고 보고 채널에 "플랫폼 보고 대기"로 표시
    - 구현 후 결과에 수정 파일과 추가한 상태 저장 방식/API를 기록할 것

          "current_delivery_id": null | 5,
          "current_destination": null | "인천항",

        ...

      "synced_at": "2026-06-09T14:00:00"
    }

    - 플랫폼 전송 실패 시 물류 업무는 계속 진행 (사일런트 무시)

  DEMO_MODE 기반으로 처리 중이므로, 이 세션에서는 EXE 패키징과 실행 안정성만 담당한다.

작업 기준:
  - 기존 start.bat은 개발용으로 보존하고, 별도 실행 파일(예: LogisticsAgent.exe)을 만든다.
  - EXE는 백엔드 uvicorn과 프론트 실행/정적서빙을 창 없이 실행해야 한다.
  - 패키징된 데모 실행 환경에서는 backend/.env에 DEMO_MODE=1을 넣어 첫 실행 시 기사/차량 시연 데이터가 자동 준비되게 한다.
  - API 키, 실제 비밀번호, 로컬 경로는 EXE나 GitHub에 포함하지 않는다.
  - 실행 로그는 CMD 창 대신 logs 폴더 파일로 남긴다.
  - 포트는 기존 물류agent 기준을 유지한다: backend 8004, frontend 3001.
  - 플랫폼에서 호출하는 /api/platform/signal 및 /api/deliveries/{id}/assign 흐름이 EXE 실행 환경에서도 유지되어야 한다.

완료 기준:
  - 더블클릭으로 실행 가능
  - CMD 창 노출 없음
