========================================
B2B 업무자동화 플랫폼 기획안
날짜: 2026-05-21
========================================

■ 이 문서는 AI(Claude Code 또는 다른 AI)가 읽었을 때
  프로젝트 전체 구조와 기획 의도를 즉시 파악할 수 있도록 작성됨.
■ 작업 이어받는 AI는 이 파일 + CHANGES.md + NEXT_TASK.md 순서로 읽을 것.


========================================
1. 우리 회사가 하는 일
========================================

B2B 업무자동화 플랫폼 기업이다.

고객사에 업무자동화 시스템을 구축하고,
그 시스템에서 발생하는 데이터를 플랫폼이 수집·분석하여
고객사 스스로 발견하지 못하는 인사이트를 제공한다.

[ 비즈니스 3단계 구조 ]

  1층: 각 고객사 맞춤 업무자동화 시스템 구축
  2층: 각사 시스템 데이터를 플랫폼 중앙 DB로 수집
  3층: AI 에이전트가 크로스 데이터 분석 → 인사이트 제공

[ 핵심 원칙 ]

  - 각사 DB는 독립적으로 운영 (데이터 주권 분리)
  - 플랫폼은 핵심 데이터만 수집
  - 회사 간 데이터 연결은 AI 에이전트가 비즈니스 맥락으로 판단
  - UX 원칙: "사람은 완료 버튼 하나만 누른다. 나머지는 자동 처리."
  - 기업은 raw DB를 직접 넘기지 않는다 (그런 시대가 아님)
    → 각사 AI가 스스로 판단·요약한 결과만 플랫폼에 간접적으로 전달하고,
      플랫폼 AI는 이렇게 누적된 간접 데이터를 분석해 인사이트와 예측 규칙을 도출한다


========================================
2. 고객사 구성 (총 5개사)
========================================

의류 서플라이체인에 속한 기업들로 구성된다.
부자재 3사 + 물류사가 하나의 생태계를 이룬다.

  [옷감사] [케어라벨사] [지퍼단추사]
       ↓         ↓           ↓
         → 해외 의류제조공장 →     ← 플랫폼 직접 고객 아님
                 ↓
           최종 의류 완성품
  [물류사]: 부자재들을 수거하여 납품처로 운송


■ 옷감회사 (1개사)
  - 의류용 원단 생산
  - 원단 종류: C(면) / P(폴리에스터) / L(린넨) / W(울) / M(혼방)
  - 컬러: BK/WH/NV/GY/BE/RD 등
  - 입출고 단위: 야드(yard)
  - 규칙 파일: 옷감agent/옷감코드_규칙.txt

■ 케어라벨회사 (1개사)
  - 의류 케어라벨 생산
  - 라벨코드 9자리가 부자재 전체를 연결하는 핵심 키
  - 규칙 파일: 라벨agent/라벨코드_규칙.txt

■ 지퍼/단추회사 (1개사)
  - 의류용 지퍼 및 단추 생산
  - 소재: 원목 / 플라스틱 / 금속
  - 소재별 출고량으로 트렌드 추론 가능

■ 물류회사 (1개사)
  - 차량과 기사를 보유한 운송업체
  - 기사 가용 일정, 차량 현황, 운행기록 관리
  - 물류 AI 에이전트가 동선 최적화 담당


========================================
3. 라벨코드 상세 (핵심 연결 키)
========================================

라벨코드는 단순 번호가 아니라 옷의 모든 정보를 담은 9자리 코드다.
AI 에이전트는 이 코드 하나로 3개 부자재사를 연결한다.

[ 코드 구조 ]

  자리  내용          예시값
  ────────────────────────────────────────
  1     브랜드코드    W
  2     계절코드      1(봄) 2(여름) 3(가을) 4(겨울)
  3     성별코드      W(여성) M(남성)
  4     품목코드      T(티셔츠) P(바지) J(재킷) D(다운)
  5     원단코드      C(면) P(폴리) L(린넨) W(울) M(혼방)
  6~7   스타일번호    01~99
  8~9   컬러코드      BK WH NV GY BE RD

[ 예시 ]

  W1WTC01BK = W브랜드 / 봄 / 여성 / 티셔츠 / 면 / 01스타일 / 블랙
  W3MJW01NV = W브랜드 / 가을 / 남성 / 재킷 / 울 / 01스타일 / 네이비
  W4MDP01BK = W브랜드 / 겨울 / 남성 / 다운 / 폴리에스터 / 01스타일 / 블랙

[ AI 에이전트 연동 방식 ]

  라벨코드 수신 시 AI가 자동으로 파싱:
    4번째 자리(품목) → 지퍼단추사에서 어떤 부자재 필요한지 판단
    5번째 자리(원단) → 옷감사에서 어떤 원단 출고돼야 하는지 판단

  예) W3MJW01NV 주문 들어오면:
    - 옷감사: W(울) 원단 NV(네이비) 출고 필요
    - 지퍼단추사: J(재킷)이므로 지퍼 필요
    - 물류사: 위 두 가지 출고 완료되면 배차 트리거

========================================
5. 자동화 흐름
========================================

  [주문 입력 - 라벨코드 기반]
      ↓
  AI 에이전트가 라벨코드 파싱
  → 필요 원단 / 부자재 / 수량 자동 도출
      ↓
  각사 생산 AI가 재고 확인 + 생산 스케줄 자동 산출
  (원자재 부족 시 발주 알림 / 납기 불가 시 경고)
      ↓
  작업자: 완료 버튼 클릭 (유일한 인간 개입)
      ↓
  플랫폼이 라벨코드 기준으로 3사 출고 현황 확인
  → 3사 모두 완료 시 물류 AI 자동 트리거
      ↓
  물류 AI: 최적 기사 배차 + 왕복 동선 최적화
  → 기사에게 자동 알림


========================================
6. 생산사 AI 에이전트 로직
========================================

각 생산사 AI 에이전트는 아래 로직으로 동작한다.

  INPUT:
    - 주문량 + 납기일 (라벨코드에서 파싱)
    - 제품별 생산속도 (사전 설정값)
    - 현재 원자재 재고량

  생산속도 예시 (지퍼단추사):
    원목단추    20개/시간
    플라스틱단추 300개/시간
    지퍼        200개/시간

  자동 처리:
    - 필요 생산시간 산출 → 시작일 역산
    - 재고 부족 → 발주 알림 자동 발송
    - 납기 내 생산 불가 → 경고 + 우선순위 재조정 제안
    - 완료 버튼 → 플랫폼에 완료 신호 전송


========================================
7. 물류 AI 에이전트 로직
========================================

  INPUT:
    - 생산사 완료 신호 (출발지, 품목, 수량, 납기)
    - 기사별 현재 위치 및 가용 일정
    - 차량 적재 용량

  자동 처리:
    - 최적 기사 배차
    - 왕복 동선 최적화 (빈차 방지)
      예) 부산→서울 배송 후 귀환 시 서울→부산 화물 자동 연결
    - 배차 확정 시 기사에게 자동 알림


========================================
8. 플랫폼 AI 인사이트
========================================

① 납기 위험 조기 감지
   라벨코드 기준 3사 출고 현황 모니터링
   → "W3MJW01NV - 옷감 완료, 지퍼 미출고 → 납기 3일 전 위험"
   → 지퍼사에 긴급 생산 요청 자동 알림

② 공급사 교체 권고
   납기 지연 원인 분석
   → "최근 3개월 지연 60%가 동일 공급업체 → 교체 권고"

③ 패션 트렌드 추론
   원목단추 출고 급증 → "프리미엄 셔츠 라인 수요 증가"
   폴리에스터 + 다운 라벨 급증 → "아웃도어 시즌 수요 증가"
   울 + 재킷 라벨 증가 → "고급 울 재킷 라인 강세"

④ 해외 의류제조사 생산 역추론 (핵심 차별점)
   의류제조사는 해외에 있어 직접 고객이 아니지만,
   라벨코드 + 원단 + 부자재 출고 흐름만으로
   해외 공장이 현재 무엇을 대량 생산 중인지 추론 가능.

⑤ 물류 최적화
   생산 완료 타이밍 + 기사 위치 + 납기 종합
   → 빈차 운행 제거 + 최적 배차 자동 수립

⑥ 자재 기반 시즌 예측 규칙화
   라벨코드 parsed_info(브랜드/계절/성별/품목/원단/컬러)를 시즌별로 누적하고
   옷감사 자재 출고 데이터와 매칭
   → "이 원단+컬러 조합 출고량 증가 = 다음 시즌 이 품목군 수요 증가" 같은
     예측 규칙을 데이터 기반으로 자동 도출
   → raw DB 직접 연동 없이, 간접 수집된 요약 데이터 누적만으로 시즌 예측 가능

9. 개발 방식
========================================

Claude Code (AI 코딩 어시스턴트) 단독으로 개발 진행.

토큰 소진 시 다른 AI에게 작업을 이어받길 경우:
  CHANGES.md  → 완료된 작업 및 변경사항 기록
  NEXT_TASK.md → 다음 AI가 이어받을 작업 상세 기록

이어받는 AI는 아래 순서로 파일 읽을 것:
  1. 기획안.txt    (전체 구조 파악)
  2. CHANGES.md    (현재까지 완료된 것)
  3. NEXT_TASK.md  (지금 당장 해야 할 것)

[ DB 기술 스택 ]
  - MySQL (각사 개별 DB + 플랫폼 중앙 DB)

[ AI 에이전트 ]
  - GPT API 사용 (보유 API 기준)

========================================
11. 데모 데이터와 AI 인사이트 검증 구조
========================================

포트폴리오 시연을 위해 4년치 공급망 데모 데이터를 별도로 만든다.

데이터 목적:
  - 플랫폼이 단순 대시보드가 아니라, 여러 agent 보고를 누적해 문제를 찾아내는 구조임을 보여준다.
  - 2023~2024년은 정상 운영 구간으로 둔다.
  - 2025년부터 자재 입고 지연이 시작되도록 만든다.
  - 2026년에는 자재 지연과 생산성 저하가 같이 나타나도록 만든다.

데이터 규모:
  - 의류 약 600만장 기준
  - 가공품 출고는 월 3~4회
  - 원자재 입고는 분기 1회
  - 원자재 지연은 3~7일 정도는 정상 변동으로 보고, 21일 이상 반복 지연부터 공급사 문제 후보로 본다.

플랫폼 인사이트 화면 원칙:
  - 인사이트와 분석을 분리한다.
  - 인사이트는 사람이 바로 이해할 수 있는 추천 문장으로 보여준다.
  - 분석은 그 인사이트의 근거 자료로 붙인다.
  - 예: 공급사 변경 후보, 자재 리드타임 악화, 생산 납기 여유 감소, 자재 지연 + 생산성 저하 복합 문제.

AI 적용 방향:
  - 외부 AI 에이전트는 당장 필수로 넣지 않는다.
  - 현재는 플랫폼 내부 분석값 + AI 인사이트 표현만으로도 포트폴리오 목적을 설명할 수 있다.
  - 실제 외부 AI 에이전트 연동은 향후 확장 옵션으로 남긴다.
  - 화면 표기는 "AI Insight" 또는 "Platform Insight"처럼 정리한다.

핵심 가치제안
========================================

"부자재 공급망 데이터만으로
 생산 자동화 + 물류 최적화 + 패션 트렌드 예측까지 가능한 B2B 플랫폼"

- 완료 버튼 하나로 생산→물류→인사이트 자동 연결

- 의류제조사 데이터 없이도 공급망으로 트렌드 파악
