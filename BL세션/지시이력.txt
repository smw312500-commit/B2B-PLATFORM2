[2026-06-12 17:00] parser GPT Vision 파싱 적용 (옷감agent BL 업로드 오류 대응)
----------------------------------------
지시: 옷감agent에서 실제 BL PDF(괄호 코드 없는 일반 양식)를 업로드하면
  "BL에서 품목을 찾을 수 없습니다" 오류가 발생. parser/main.py의 정규식 파서는
  `[COTTON_YARN]` 같은 괄호 코드 표기만 인식해 일반 BL 양식을 못 읽는 문제 확인.
  세션_지시문.txt 원래 설계대로 GPT Vision 기반 파싱으로 교체할 것
  (OpenAI API 키 사용자 제공).

결과:
  - parser/bl_parser_gpt.py 신규 — PyMuPDF(fitz)로 PDF 페이지를 PNG로 렌더링 후
    GPT-4o-mini Vision(JSON 모드)으로 BL 정보 + 품목을 파싱.
    품목별로 matched_material(한국어 원자재명: 면/폴리에스터/린넨/울/혼방 원사,
    라벨원단, 잉크, 원목, 플라스틱원료, 금속원료, 지퍼테이프, 염료 중 매칭),
    matched_qty, matched_unit, confidence를 함께 반환.
    MATERIAL_CODE 매핑으로 main.py의 CODE_NAMES 코드(COTTON_YARN 등)와 연결.
  - parser/main.py — /parse-bl에서 GPT 파싱을 우선 시도하고, OPENAI_API_KEY가
    없거나 GPT 결과에 품목이 없으면 기존 pdfplumber 정규식 파서로 자동 대체(폴백).
    응답 스키마(BLResult: bl_number/shipper/port_of_loading/port_of_discharge/
    vessel/eta/items[])는 기존과 동일하게 유지해 각 agent 프론트와 호환.
  - parser/requirements.txt — openai, pymupdf, python-dotenv 추가.
    (pdf2image+poppler 대신 PyMuPDF 사용 — Windows에 추가 설치 불필요)
  - parser/.env (gitignored) — OPENAI_API_KEY 저장. parser/.env.example 추가.
  - parser 전용 venv 생성 후 위 의존성 설치, uvicorn --port 8010으로 재기동.
  - 테스트: PyMuPDF로 생성한 BL 텍스트 PDF(원단 품목 5종 + B/L NO./선적항/도착항/
    선박/ETA 포함)를 /parse-bl에 업로드 → 전 필드 정상 추출 및 원사 코드 매핑 확인.
